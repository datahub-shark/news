这个插件在原来高性能后端的基础上，做了一些优化，使得这个插件更加易用，支持闭链，可以直接导出ROS2包和Mujoco XML

ps. ROS2包还是URDF，URDF本身无法直接描述闭链机构，还是需要一些空Link然后手动连接

基本功能：

1. 引入了机构图，可以一键导出闭链

抛弃了Link树，通过LinkCard相互连接的方式来表达闭链机机构。

一个LinkCard可以包含任意多个零件/装配体；一个LinkCard可以有多个连接点，不同的连接点相互连接可以自动形成对应的Joint（但是Joint约束还要自己输入），用户不再需要在脑子中理清楚神秘的Link树层级和空Link等等，直接按照机械结构把LinkCard连接起来即可

2. 无需用户自建轴和坐标系，可自动算出

原先的sw2urdf插件在定义joint的时候需要用户自己画轴和坐标系，十分繁琐。

swDescribe支持直接选择零件特征，自动算出所需的轴和坐标系，便捷了许多


3. 总体预览中添加了Joint角度预览，可以直接查看运动过程

(忽略掉上奇怪的装配, 嘘。。。。。)

4. 针对轻量化零件的缓存调整

之前ros官方的sw2urdf在处理轻量化零件的时候会直接还原所有零件，导致在导出大型装配体的时候速度会非常缓慢。而现在的swDescribe会优先使用装配体/零件中已存有的质量等数据，仅仅还原部分所需的轻化零件。

但是注意，解析轻化零件这步还是比较耗时的（不知道SW怎么搞的，速度感人啊......），所以大觉还是要有些耐心，但是在一次编辑中，只要解析一次之后就会有缓存，之后就可以跳过“解析轻化零件”这一步骤了

4. STL导出优化

一些仿真软件对于模型面数有一定要求，这个插件也提供了stl的面数上限设置和QEM优化，直接在“STL导出设置”进行设计即可

5. 导出STL修复

在导出的SW工程中，可能一些零件为STEP，而这些STEP或是零件本身在SW解析时可能是正常的，但是在导出成STL之后可能会出现“非流性边缘”和“开放曲面”的问题。针对这个问题，本插件也提供了两种解决方案：

1.提供基础的破面修复

2.使用SolidWork原本的 STL Saveas 导出器来导出。但是经过试验，这一步通常不会有很大作用。如果破面修复无法解决，大部分情况为原本零件出现问题。如果这些破面不影响仿真，可以考虑保存，而不修复。

6. Agent支持

swDescribe提供了一套Skill和相关接口，用户可以直接使用Deepseek和GPT等模型，来一键生成工程和Mujoco XML

我目前测试了Deepseek-V4.1-Flash 1017(MAX)和GPT-6.1 Sol(High)，不出所料GPT-6.1 Sol会更好一点，Deepseek Oneshot的结果也还行，但是在实际使用中可能在某些地方需要微调，因为在这套Skill下AI会偏向通过SW的装配和零件名称来理解模型，这就和实际装配有较大关系了。

可以发现GPT-6.1 Sol完成度相当高，连摩擦轮和电池仓盖都理出来了（这部分可以通过提示词约束一下），但是第一轮还在装甲板的固定和一些细节上出了问题，GPT-6.1 Sol会把装甲板和大腿装配在一起，导致二者一起转。第二轮给出反馈后，XML基本可用。两轮总共用时25min左右。以下是二轮调整后的XML导入mujoco仿真后的画面。


Deepseek效果有些不如GPT-6.1 Sol，第一轮在装配上理解还不是很全面，比如第一轮出来后，DS没有理出云台（估计是提示词的锅......）。在经过两轮反馈后，XML基本可用。但是生成的机构图效果不如GPT-6.1 Sol适合人类理解，而且总时间耗时在35min左右。以下是三轮调整后的XML导入mujoco仿真后的画面。

对于复杂装配体，如果是手动编辑机构图的话，我建议是先在SolidWorks中把零件归进文件夹中，然后直接选择该文件夹添加进LinkCard，插件会自动把文件夹中所有的零件添加进该LinkCard
