BeamLock | RM2026-雷达云台激光反制开源

仓库地址：https://github.com/SZURPVision/RP-26BeamLock

RP-26BeamLock 是深圳大学 RobotPilots 战队 2026 赛季雷达系统的云台分系统：接收雷达主程序通过 UDP 发来的敌方无人机坐标，用相机做视觉伺服，把激光指向对方无人机上的激光检测装置并持续照射完成反制，覆盖目标检测、命中判定、云台控制、通信与全套标定工具。

本次开源的是云台分系统：雷达主程序与云台电控固件不在开源范围内。为了让手上没有这套硬件的同学也能把工程真正跑起来，仓库内提供了通信协议文档、上游雷达模拟器、电控串口模拟器

今年我们雷达全国赛平均反制时长129.4秒，南部赛区平均反制时长48.5秒，能较为稳定的完成二级难度的反制

1. 核心亮点

  • 上层给坐标，下层做闭环。 雷达主程序只下发"目标在雷达坐标系下的米制坐标"，角度解算、扫描与锁定全部在云台侧完成。云台先用自己的标定结果（雷达→云台外参）把坐标转到云台角，随即切入图像域的视觉伺服。这样做的原因很直接：激光在图像中的位置随距离变化，纯几何解算对测距误差非常敏感（距离误差30厘米以上就可能脱靶），而像素闭环对测距误差、外参残差都不敏感。
  • 相机直出 BayerRG8，省掉每帧一次全图转换。 彩色转换在任何位置都会带来明显的每帧开销。检测链路直接用 2x2 卷积核提取颜色特征，再经自适应阈值、形态学处理与轮廓分析完成"灯条 → 灯条行 → 目标"的组装与打分；命中判定使用在线 2-means 自动分离"被照射/未被照射"两类亮度，不需要人工标定命中阈值，保证了在各种色彩情况下的稳定性。
  • 扫穿求圆心的动态标定。 未命中时在预设落点周围做同心圆扫描；当扫描扫过命中区域（miss→hit、hit→miss 两个边沿）时，取弦中点估计激光位置，用卡尔曼滤波修正激光偏置。锁定后连续 10 帧未命中会重新进入扫穿校准。标定误差由此变成一个"运行中持续收敛"的量，对现场标定的要求大幅降低。
该标定逻辑在预先标定完全失效的情况下，只要激光可以纠正回大致位置，扫描能飘到目标就有拉回来的可能
  • 全链路可观测。 图像、目标与激光标注、云台目标角/实际角、网络包与日志统一通过 Foxglove 输出，可同时录制 mcap；Tools/Export 能把 mcap 导出为视频，方便离线复盘与调参。

2. 系统简介

2.1 背景与目标

雷达反制要求把激光稳定地打在对方无人机的激光检测装置上并保持一段时间。这条链路里，目标由雷达给出、执行由云台完成，中间横跨三个坐标系（雷达坐标系、相机坐标系、云台角），还叠加了图像处理延迟、云台响应延迟与测距误差。

RP-26BeamLock 把"从坐标到锁定"这一段的全部问题收敛到云台侧解决：仅接收上游坐标做粗引导，用相机检测目标与光斑做精跟踪，并用命中反馈做长期自校准。

2.2 职责与处理链路

链路方向传输方法频率
目标位置雷达主程序 → RP-26BeamLockUDP 9000端口约 5 Hz
心跳/状态RP-26BeamLock → 雷达主程序UDP 9001端口1 Hz
云台控制RP-26BeamLock ↔ 云台电控串口通信下发约 1 kHz，反馈由电控决定

一帧的完整流程：UDP 取到最新目标坐标 → 相机取帧（BayerRG8）→ 检测目标与激光点 → 计算目标中心与预设激光点的像素误差 → PID + 前馈算出云台角速度 → 云台侧做速度/加速度受限的轨迹规划 → 串口下发目标角；同时通过 UDP 心跳把自身状态上报给雷达主程序。识别帧率在正常情况下可达 130 FPS 以上。

2.3 状态机与扫描策略

  • Tracking：检测到目标后进入视觉伺服。
  • Lost：目标丢失后保持当前角度，等待 reset_time_threshold（默认 5 s）超时。
  • Scanning
    • line：绝对角度逐行扫描（yaw 来回扫、pitch 逐行步进），不依赖雷达数据；
    • square：以雷达给出位置为中心的方形扫描，适合雷达引导可用但相机视野很小的情况。

扫描模式可在启动参数中切换（--scan-mode line|square），角度幅度、周期、行距、速度全部由配置文件给出。

2.4 开源范围与仓库边界

  • 包含：云台分系统的全部自有代码——目标检测、视觉伺服与云台控制、通信（UDP + 串口）、Foxglove 日志与录制、全部标定与调试工具。
  • 不包含：雷达主程序（上游）、云台电控固件（下游）。二者与云台之间的接口在 docs/PROTOCOL.md 中逐字节写明
  • 替代方案：Tools/NetworkTest/server_test 可以模拟雷达主程序，Tools/SerialTest/serial_simulate + socat 可以模拟电控

3. 关键实现

3.1 目标与激光点检测

检测对象是无人机上的激光检测装置：

  • 用 2×2 卷积核直接对 BayerRG8 图像提取颜色特征，避免彩色转换开销；
  • 自适应阈值 + 膨胀/开运算/中值滤波得到候选亮斑；
  • 轮廓 → LightBlob → 按 y 临近与 x 间距组装 LightRow（三灯条成行）→ 两行组装成 Target，按评分选最优目标；
  • 激光点在图像中的位置由标定出的激光光路（x = Az + B、y = Cz + D）按距离投影得到，再叠加运行时收敛的偏置。

理论上光圈给大一点也能锁三级（在家里测的），重铸传统荣光吾辈义不容辞

3.2 命中判定与激光偏置的动态标定

命中判定与动态标定是这套系统里最精髓的部分：

  1. 裁判系统被照射时会变色，具体体现为红蓝灯一起亮。因此对目标区域的亮度做在线 2-means，自动维护"未照射/被照射"两个聚类中心，两中心分离度满足阈值后才判定命中，无需人工设阈值；
  2. 首先假设我们的伺服足以将估计的激光落点锁在目标中心；
  3. 当未命中时在跟踪基础上叠加同心圆扫描，让激光扫穿识别区域；
  4. 检测 miss→hit 与 hit→miss 两个边沿，取两点连线的弦中点作为激光落点的新估计；
  5. 更新出的偏置被叠加到预先的标定结果上，动态更新激光落点；
  6. 更新后若连续 10 帧未命中，则重新进入扫穿校准。

5. 快速上手

5.1 环境要求

  • Ubuntu 22.04 / 24.04（x86_64），支持 C++20 的编译器，CMake ≥ 3.10；
  • OpenCV、Eigen3、yaml-cpp、Boost（Asio/Beast）；
  • 海康 MVS SDK，只想验证编译时可用 -DUSE_FAKE_MVS=ON 走仓库内置的空实现。
  • Foxglove SDK 由 CMake 在构建时自动从官方 Release 下载（可用 -DFOXGLOVE_DOWNLOAD_URL 换镜像）；
    不需要可视化时用 -DUSE_FAKE_FOXGLOVE=ON 完全跳过。

5.2 编译

git clone https://github.com/SZURPVision/RP-26BeamLock.git
cd RP-26BeamLock
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
./build/App/beamlock                 # 默认逐行扫描
./build/App/beamlock --scan-mode square --no-image-log

没有海康 SDK 时的编译验证：

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release -DUSE_FAKE_MVS=ON
cmake --build build -j

5.3 无硬件测试

缺什么怎么办
雷达主程序./build/Tools/NetworkTest/server_test：向本机 9000 端口以 10 Hz 发假目标，支持交互式修改 x/y/z/allow_counter
云台电控socat 造一对虚拟串口 + ./build/Tools/SerialTest/serial_simulate 按协议回包

相机暂无替代方案：主程序需要真实相机取流

5.4 标定

系统有三处需要标定，仓库内都有对应工具，详细步骤见 docs/calibration.md：

  1. 相机内参（CameraTune）：棋盘格标定，写入 CameraConfig；
  2. 激光光路（LazerCalibration）：固定云台，用不同距离下的激光光斑拟合 x = Az + B、y = Cz + D，得到 x_k/x_b/y_k/y_b；
  3. 雷达→云台外参（LidarGuideCalibration）：采集若干组「雷达坐标 - 云台角」对应数据，解出平移与 ZYX 欧拉角，写入 guide_translation / guide_rotation_euler_zyx_deg。

整套方案对标定精度的要求不高：距离误差控制在 0.5 m 内、光斑拟合误差在半个像素内即可，剩下的交给动态标定。
