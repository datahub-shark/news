本次开源的是 TCR 在 RoboMaster 2026 赛季使用的完整雷达站系统。系统由地面视觉、无线电与无人机反制三部分组成。地面视觉与无线电通过本机 TCP 交换阵营、干扰等级、密钥、坐标和比赛信息，共同完成雷达数据的获取、融合与发送；地面端通过独立 A7 串口向反制计算平台同步本局反制次数。

当前稳定版本采用单块 AD9361、单接收通道、分阶段切换。运行顺序为“一级干扰波成功 → 二级干扰波成功 → 信息波”。信息波坐标是主要来源，地面视觉负责回退与容错。这套方案结构简单，已经完成实战验证。

按现有统计口径，正常状态下单场累计易伤时长最高达到 2070+ 秒，正常场次平均稳定在 2050+ 秒。全国赛局均易伤时长较低的原因是运算平台断电/裁判串口线等非软件问题（导致数局易伤为0/极低）。

1. 系统定位

固定机位视觉会受到遮挡、盲区、远距离小目标和光照变化影响。信息波不依赖本队相机视野，在本赛季的比赛环境中表现稳定。因此，系统优先使用新鲜有效的信息波坐标，并在无线电坐标过期时切换到地面视觉。

这套设计发挥了两种来源各自的优势：无线电提供稳定、完整的主要坐标，视觉提供独立的回退能力和直观的现场画面。


2. 当前稳定方案

比赛系统包含三个核心进程：



- 地面视觉主进程负责图像识别、场地定位、坐标融合和裁判系统通信。

- 无线电主进程负责 AD9361 控制、干扰波与信息波解析，并通过 TCP 输出数据。

- 无人机反制进程负责长焦检测、Boresight 偏差、云台目标角度和第 3 次后的配置切换。




地面视觉与无线电在同一台计算机上运行。无线电作为 TCP Server，地面视觉作为 Client。无线电坐标进入地面端后完成新鲜度判断和来源选择，最终由地面端发送至裁判系统。反制使用独立计算平台和串口，辅助链路故障不会占用裁判串口，也不会阻塞地面视觉与无线电主流程。


无线电在任一时刻只使用一个接收配置。一级解码成功后切换到二级，二级成功后切换到信息波。比赛期间采用串行状态机处理波形，降低了硬件、供电、接线和进程管理的复杂度。



详细架构、通信字段和频点配置见 [系统架构文档](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/docs/ARCHITECTURE.md)。


3. 硬件选型

当前单板比赛链路围绕 433 MHz 频段搭建。硬件选型如下：


| 比赛主链路 | AD9361 SDR（AIDOSDR A3） | 1 | 当前单板方案的射频收发与 IQ 采集 |

| 比赛主链路 | 433±10 MHz 带通滤波器 | 1 | 抑制工作频段外的信号 |

| 比赛主链路 | 433 MHz 八木天线 | 1 | 提供 400～470 MHz 频段的定向射频链路 |

| 比赛主链路 | 50-7 馈线，3 m，SMA 公对公 | 2 | 连接天线、滤波器与 SDR |

| 调试设备 | NanoVNA-H | 1 | 检查天线、馈线和滤波器的射频特性 |

| 研究设备 | AD9363 NanoSDR | 2 | 单板双波与多板方案研究 |

地面识别选型：MV-CS200-10UC（相机） + MVL-KF1224M-25MP（镜头）
反制选型：MV-CS060-10UC-PRO（相机 ）+ MVL-MF3518M-5MPE（镜头）

AD9361 A3 是当前正式方案的核心板卡，现有程序已经围绕其 `libiio` 接口和比赛状态机完成适配。433 MHz 带通滤波器、八木天线和低损耗馈线组成射频前端。NanoVNA 用于射频链路检查。两块 AD9363 NanoSDR 服务于AD9361单板项目测试以及后续研究，v1.0.0 比赛部署只需一块 AD9361 主板。


射频测试需遵守当地无线电管理规定、比赛规则和场地要求。推荐使用录包、衰减器、假负载或屏蔽环境完成日常验证。详细要求见 [无线电安全文档](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/docs/RADIO_SAFETY.md)。


4. 主要工作

4.1 无线电

无线电模块基于南京理工大学江阴校区 Combat 战队公开的 `CombatRadarSdr2026` 继续开发。TCR 完成了以下主要工作：



- 重构地面通信结构，由无线电统一管理本机 TCP Server。

- 增加信息波专用的低延迟软判决解码路径。

- 建立单板比赛状态机，实现两级干扰波与信息波的连续切换。

- 使用 latest-value 机制发送坐标，网络阻塞时保留最新结果。

- 增加断线重连、连接代次隔离和阵营切换清理。

- 增加录包、回放、模拟器、日志和无硬件测试。



AD9361 IQ 数据经过瞬时频率计算、GFSK 符号判决、接入码搜索、候选筛选和裁判帧解析。长度、命令、CRC 和坐标范围校验通过后，数据才会进入融合链路。

完整改动清单见 [与上游代码的差异](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/CHANGES_FROM_UPSTREAM.md)。



4.2 地面视觉

地面视觉基于 HKUST ENTERPRIZE 2025 雷达站方案完成调教和集成。当前链路包含车辆检测、装甲板颜色与状态识别、数字分类、目标跟踪和场地坐标转换。

项目采用 YOLO 模型训练。使用者可以获取港科大公开数据集，按仓库配置重新训练，并在部署设备上导出 TensorRT engine。训练与导出流程见 [模型训练文档](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/docs/MODEL_TRAINING.md)。


4.3 融合与通信

融合模块按数据年龄选择坐标来源。新鲜信息波坐标具有最高优先级；信息波过期后使用地面视觉；短时异常场景可使用旧信息波或盲猜结果兜底。所有来源均带有时间戳和来源标记，便于赛后复盘。

TCP 发送侧按命令类型保存最新值。新坐标会覆盖尚未发送的旧坐标。连接重建时会清理旧状态，避免陈旧数据进入新比赛链路。

详细实现见 [README](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/tree/v1.0.0#readme) 和 [系统架构文档](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/docs/ARCHITECTURE.md)。


4.4 信息波多机通信

信息波除坐标外，还包含机器人血量、剩余发弹量、宏观状态和增益效果。地面端将 `0x0A02～0x0A05` 分别存入四个 latest-value 槽位，再封装为裁判系统 `0x0301` 机器人交互数据，子命令为 `0x02A1`。



信息波 0x0A02～0x0A05

→ 最新值缓存与时效检查

→ 0x0301 / 0x02A1

→ 裁判系统

→ 我方英雄、工程、3/4 号步兵和无人机


数据包包含版本号、有效位、过期位、波形等级、包序号、会话 ID，以及四类数据各自的原始序号和年龄。机器人端可以据此识别缺失、过期、重连和换场数据。新连接或比赛阶段切换会生成新会话并清空旧缓存。

有效数据默认向五台机器人轮询发送，每台最高 5 Hz，总频率约 25 Hz；全部数据缺失或过期时降至每台 1 Hz。多机信息使用低优先级、忙时丢弃策略，密钥提交、易伤决策和 `0x0305` 坐标发送保持更高优先级，串口拥塞时不会积压历史信息。
`0x0305` 负责向选手端小地图发送融合坐标，`0x0301 / 0x02A1` 负责向我方机器人分发信息波中的非坐标数据。两条链路共用裁判串口，由统一发送调度器管理。实现与默认频率配置见 [`info_wave_bundle.py`](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/ground_vision/driver/referee/info_wave_bundle.py) 和 [`params.yaml`](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/ground_vision/config/params.yaml)。

4.5 无人机反制与双机通信

反制模块使用长焦工业相机和 YOLO 检测激光模块，依据 Boresight 计算像素偏差，再换算为 pitch/yaw 目标角度发送给云台控制板。相机、推理、录制、云台串口和界面均在独立进程运行。

地面端读取裁判系统 `0x020C`，根据己方空中机器人反制状态的边沿变化累计本局次数。次数通过另一条串口发送到反制计算平台，帧格式为 `[0xA7, count, CRC8]`，反制端回复 ACK。A7、裁判系统和云台控制使用三个独立串口，均支持坏帧重同步、断开与自动重连。

达到 3 次后，反制端可以切换曝光、增益或模型；新回合归零时恢复初始配置。默认配置稳定完成前三次具有实战依据。第 3 次后的软件链路已经补齐，第 4～5 次仍需要整机验证。


完整参数、接线、协议和权重哈希见 [反制模块说明](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/counter_drone/README.md)。

5. 实战与验证结果

5.1 实战表现

开局2s内稳定解1级干扰，10s裁判系统冷却后稳定解2级干扰

| 正常状态单场最高累计易伤时长 | 2070+ 秒 |

| 正常场次平均累计易伤时长 | 稳定在 2050+ 秒 |

| 正常场次平均反制时长 | 稳定在 135.0 秒 |

国赛部分低/零易伤时长场次出现电脑电源线未连接、裁判系统串口3-pin 线故障等硬件链路问题。相关场次反映了供电和接线检查的重要性。当前方案的软件链路在正常设备状态下保持稳定。

公开测试包从一份 9,907,994,624 bytes 的赛场单通道录包中裁剪，包含一级干扰波 2 秒、二级干扰波 1 秒和信息波 2 秒。当前生产同源解码结果如下：


| 一级干扰波 | 211 个有效密钥帧 |

| 二级干扰波 | 112 个有效密钥帧 |

| 信息波 | 97 个有效信息帧，其中 `0x0A01` 20 帧 |


测试包提供参数清单、SHA-256、许可证和一键校验脚本。详细实验数据与证据边界见 [实验结果](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/docs/EXPERIMENT_RESULTS.md) 和 [公开 IQ 说明](https://github.com/coach114514/TCR-RM2026-Radar-OpenSource/blob/v1.1.0/docs/PUBLIC_IQ_SAMPLES.md)。
