前言

RoboMaster 26 赛季，规则新增了自定义客户端。经过从 0 到 1 自主开发，客户端终于从区域赛开始登上赛场，此后又历经大量实战考验，始终稳定可靠。比赛结束后，我们希望把它开源出来，为其它队伍提供一些参考，也期待大家的交流与改进。本次开源包含了完整的自定义客户端代码。

技术选型

  1. 在图形界面方面，我们没有采用 Qt、Electron 等传统桌面应用框架，而是选择 Dear ImGui 作为主要 GUI 框架。Dear ImGui 属于即时模式 GUI。与传统 GUI 框架维护大量控件对象和事件状态不同，ImGui 的界面会随着程序主循环不断重新构建。对于普通软件而言，这种方式未必具有优势，但该软件的界面主要由持续变化的视频画面组成，因此即时模式 GUI 与其业务特点具有较高的匹配度。
  2. 在网络通信方面，该软件采用 Asio 框架，并结合 C++20 协程实现异步网络通信。Asio 能够在单线程事件循环中同时处理多个网络连接，从而避免为每个连接分配独立线程，减少额外开销。在 MQTT 通信部分，该软件采用 async_mqtt 库，该库原生支持 Asio 风格的异步 I/O，同时提供的接口足够底层。
  3. 对于视频解码，我们选择使用 ffmpeg 进行解码。因为 ffmepg 体积较大，所以我们对 ffmpeg 内核进行裁剪，只保留 h264 和 hevc 格式的解码，解码方式只支持了软解码和 nvidia 硬解码，成功减小了软件体积。分析 msvc 编译器在编译时生成的 map 文件可以得出它在最终的可执行程序中只占用 3.4M。
  4. 对于线程间通信，我们选择使用 readerwriterqueue 框架的无锁队列。比起使用 mutex 线程锁，它的性能开销更低。
  5. 为了进行赛后分析复盘，我们使用 spdlog 记录日志，并实时存储所有网络通信数据。

系统架构

系统采用分层设计，分为 IO 层、解码层、逻辑层、UI层。将高频 IO、计算密集型视频解码和 UI 渲染进行解耦，并通过无锁队列完成不同阶段之间的数据传递。这样既可以保持网络接收的连续性，也能够避免阻塞 UI 主线程。

小巧思

自定义客户端不仅在客户端展示比赛数据，还会从裁判系统下发的 GlobalUnitStatus 中提取敌方英雄、工程、步兵和哨兵的最新血量，将其紧凑编码后封装进 CustomControl，再传至机器人。这样，电控可以进一步处理和展示敌方血量，为操作手的目标选择与战术判断提供更直观的信息支持。
