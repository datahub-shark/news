学习资源：

   如果不是通信专业的同学，射频知识应该是比较令人困惑的，我个人是HAM，我也有一点建议大家可以买一本《业余无线电通信》看一眼（不过其实信息密度不算高），至少了解一些基本的理论知识，接下来我可能要建议买本《微波工程》，但不用急着深入。

   软件使用（如GNURadio/Matlab+Simulink），我个人建议是多搜Google，多问AI，多找别人写的实验code做学习（b站有不少视频以及相关演示资源），这些软件的很多模块描述都十分抽象，但是AI的理解却意外的好。


针对于还没上手的队伍的工作流程建议：

   这个我和很对人都说过，就是我们今年目标先放在解干扰源，无线包payload因为就是串口通信那个协议，所以可以直接用老的代码，而协议包结构部分（也就是前面的前导码和两个重复的payload length），这个其实就是 GNURadio 里面的 Default Header Format Obj [1]的结构，可以直接在流图里面做判断解包，不需要自己写状态机；有余力的队伍接着往下做广播源解析解调，V1.4.x目前难度已相当简化，只是需要考虑更多的信道衰减，可能需要外挂放大器和高增益天线，以及软件内进行带通滤波，后面的章节会稍微讲解。


软件

   GNURadio是我最熟悉的工作流，gr的网上教程与示例相对比较丰富，内置的模块应付目前的规则基本足够（目前看来组委会也在用GNURadio），可以很方便的dump Python脚本，方便做后续的二次开发和融合，也比较容易和Python现有的一些DSP库做整合（比如Numpy和SciPy），据说还有gr-cuda可以将计算部署到GPU，但我还没用过。

   Matlab & Simulink其实也是一个很不错的选择，而且考虑到Matlab和Simulink有生成FPGA编程所需HDL代码的工程能力，可以方便以后卸载部分工作到FPGA，按理来说这个应该蛮不错的，但是主要是我不熟，所以无法提供太多建议。


PlutoSDR

振荡器校准：

   个人使用的是一个国仿Pluto（√），其出厂并没有设置振荡器校准值，也就是说它会使用固件中默认的振荡器频率也就是40MHz，而实际上这个晶振是比40MHz偏低了几十Hz的，在PLL倍频后产生了几百Hz的LO频率偏移，

   应该使用一个频率精准的频谱仪或者电台，对振荡器校准值进行调试。


发射功率：

   个人手上的Pluto在433MHz时，Tx衰减设置为0（gnuradio里面，PlutoSDR sink的那个是attenuation，不是Gain）时，输出功率为3dBm，但不排除各位手上的SDR设备会有不一样的表现，因为AD936X输出是一个差分信号，链路上会至少使用一个巴伦完成到单端信号的变换，而巴伦的插损其实有点不太可控，不同型号的巴伦插损是千差万别的，最好还是用个频谱仪标定一下。


接收增益：

   如果使用SDR设备，我在这里建议大家外挂至少一级LNA，AD9363的内置Rx放大器的噪声系数其实挺一般的（Max Gain的情况下NF为3左右），而一个优质的外挂LNA可以压低全系统的噪声系数，例如我们加一个QPL9547前级LNA，5V Vin，65mA偏置电流设置下，该级提供约20dB增益，噪声系数为0.3，在后级同样开满增益的情况下，可以实现理论最大0.3319的系统噪声系数。

（我们的LNA模块在开源路上了，很快！）


前置滤波：

   PlutoSDR为代表的SDR设备，其射频前端的复基带处理链路上一般具有一个性能尚可的可编程低通滤波器，以及数字域上的FIR滤波器，这些会在你配置SDR设备时完成，虽然对于研发环境是够用了，但对带外干扰信号拒止能力其实有限，强EMI环境下可能表现不稳定，因此我仍然建议配置一个外部的预选滤波器，我目前已测试B39431B3710U410，测试结果表现良好（图为B39431B3710U410 + 一级QPL9547，其中QPL9547提供了约25dB的增益）

其他SDR的小问题

   我目前听说有队伍的璞致P203Pro，使用2x2MIMO模式接收时有意外干扰的情况，目前尚不明确是TX端本振泄露还是板上EMI干扰，目前他们那边仍在排查；

   目前已有明确知识表明，部分AD936x的SDR设备如果配置中未禁用TX通道，TX通道会在未接受到数据的情况下发射本振信号[2]，所以可能要注意，在不使用SDR设备的TX通道时，可能需要显式的关闭TX通道，或将TX通道设置为最大衰减值（目前倒是没发现原版1x1 PlutoSDR有这个问题），并将不需要的通道（无论收发）端接50ohm假负载作吸收（无论什么设备都建议这样做），避免产生意外的EMI发射。


阻抗匹配：

   发射源端，传输线和负载端都需要同一特征阻抗才能传输最大功率，特征阻抗由感抗、容抗和纯电阻合成，在射频系统中，前两者占相当大一部分；大多数实验用射频系统应该用的都是50ohm阻抗，只有一些电视等基础设施在使用75ohm，买线材，天线的时要稍微注意一下。


天线：

   这段时间和某位朋友聊了一下，发现他买了一根增益为 38dBi 的433MHz的天线，这个显然就是被骗了，其对应的有效口径接近300m2，这玩意弄一个射电望远镜可能勉强能达到，我仍然建议各位学习一些基本的射频和天馈相关知识，如前所述，至少可以看看《业余无线电通信》，这样至少不会被坑的那么惨。

   吸盘天线：

       这个我感觉是最垃圾的天线，各种参数，特别是增益严重虚标，就这一点就可以毙掉了；这种天线结构属于中部加感GP（垂直接地）天线，中部加感是为了缩小体积才使用的手段，会降低不少发射效率；我买的标注中心频率为433MHz，实测谐振频率稍有偏移，最低点驻波大概在1.5，还能用，但提醒一下各位已经买了这玩意的队伍，它有一个非常抽象的问题：这个天线虽然配置了磁吸底盘，但不可以真的吸在金属板面上，它只能粘在非金属板面上，否则谐振频率马上就要偏到天上，在433MHz完全就不匹配了。


   羊角天线/羊角天线/T形天线/FPV天线：

       评价为夯，这个天线本质上就是一个半波长偶极子天线（DP天线），它在便宜（约15元）皮实（软弹钢丝）的同时，增益也是可以预期的（1dBd = 2.15dBi），而且DP天线属于一个非常非常基本和简单的结构，隔壁学校BG7LFY剪钢筋手搓了一个都好用，这要是都做不好，干脆别开厂了（）；

       不过提醒一下，不要买长线版本，这个天线自带的线是RG1.37的，非常细，长了损耗非常大。


   玻璃钢天线：

       评价为人上人-顶级，这玩意越长增益越高，商家可能虚标增益，但至少没有虚那么多，谐振也是准的，但需要一点射频知识才能不踩坑的买，主要是玻璃钢天线分成需要地网和不需要地网两种，前者结构上算是一个垂直接地天线（GP），而后者是一个不知道啥玩意的结构（可能是匹配过的GP，也有可能类似于偏馈/长线天线），具体属于哪种，需要如何配置还需要问商家。


   八木天线：

       评价为夯，一般来说谐振频率准，增益高，六单元尺寸算下来刚好合规（应该不会超出雷达传感器台的宽度），对于弱信号（如广播源信号）接收能力好，而且强指向性也意味着收到非目标方向的干扰会更少一点；价格也不算很贵，一只全新的不超过100元，不过有隔壁ham反应说买到了谐振频率有偏移的残次品，建议到手找个网分打一下，不合规就退货。


   买SDR送的小天线：

       这个我十分不建议使用，评定为拉，主要是因为这玩意就不是设计用于433MHz高效收发的，尺寸太短；我虽然没测试，但我猜在433MHz上是完全不谐振的，临时调试可以，别认真用。


大佬可以跳过的Filter小提示：

   V1.4.0开始，因为不需要再担心系统动态范围问题以及同频干扰问题，我们现在可以大大方方使用PlutoSDR等12bit接收机去同时采集干扰源和广播源，然后在数字域上面把对方滤掉；虽然我还是那句话：强烈建议各参赛队将自研高分辨率外差/超外差接收机的事项提上日程，说不定明年就要回归V1.3.0，但至少今年的先弄一弄，凑合一下。

   FFT Fliter和FIR Filter是两种比较常用的滤波器模块，它们需要配合设计好的FIR Taps参数，或者FIR Taps生成器对象来使用，GNURadio 里面的 Band-pass Filter Taps 会是我们接下来可能会用到的Taps生成器，其中我们主要讲Transition Width，Window，Beta相关的问题；

   （这里还推荐一个FIR的Playground...不过其实你更应该使用GNURadio自带的那个Filter design tool，但这个网站的信息会更简洁一点）

   Transition Width就是过渡带宽，对于二/三级步步紧逼的干扰源，一个过渡带很窄，滚降很快的滤波器是有必要的，然而，快速滚降->高滤波器复杂度->更多Taps->更大的计算量，对此我们有两种缓解方法：1，卸载这部分工作到高性能计算平台上，如FPGA或GPU（然而如前所说，我还不会）；2，使用FFT Filter代替FIR Filter，虽然FFT Filter延迟更高，不太适合动态调整，但是目前的规则上我们还不需要担心这些问题，而且还有一个好处，GNURadio的FFT Filter实现了多线程并行处理，这有利于充分利用Host的算力。

   Window和Beta，首先是Window的挑选，我们目前主要考虑带外的幅度抑制，在几个可选项中，Blackman和kaiser会是比较好的选择，而其中的kaiser还需要额外设置一个Beta值（Band-pass Filter Taps里面默认会有一个Beta的输入框，但是只有Window选用kaiser才起效），比较简单的理解，beta值越高，其对于带外信号的抑制性越强，在V1.4.x当中，可能需要beta>40的kaiser窗才能满足带外抑制的要求；此外，如果你使用GNURadio 的 Filter design tool 生成 Taps，则你可以拥有更多窗函数的选项，比如带外抑制效果比Blackman更好的Blanckman-Harris窗。
