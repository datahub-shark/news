MemRW3：MCU 实时变量采集与源码调试工具 ---- 可作为Ozone的低配泛用平替

Nguồn: RoboMaster BBS · Tác giả: liao

Chuyên mục: Cơ khí

开源一个自己写的MCU 实时变量采集与源码调试工具：MemRW3

它基于 Rust、egui 和 probe-rs，支持 CMSIS-DAP、ST-Link、J-Link，以及 SWD/JTAG 协议，可以直接解析 ELF/DWARF 中的变量和源码信息。

项目主体使用 Rust 编写，无额外动态依赖，高性能的跨平台调试工具。

项目地址：MemRW3

中文字体显示

MemRW3 启动时会自动查找系统中的中文字体。如果界面中文显示为方框或缺字，可以安装 Noto Sans CJK 或思源黑体，然后重新启动软件。

Ubuntu：

sudo apt install fonts-noto-cjkfc-cache -fv

Windows 可以安装“微软雅黑”中文语言字体，或者下载 Noto Sans CJK SC 后右键选择“安装”。

macOS 可以通过“字体册”安装 Noto Sans CJK SC 或思源黑体。

启动成功后，终端会显示实际使用的字体

如果仍提示未找到字体，请确认字体已经安装到系统或当前用户的字体目录，并重启 MemRW3。需要注意，文字显示为方框通常是缺少字体；如果显示成完全错误的字符，则更可能是文件编码问题。

Chart：实时采集与波形分析

加载带 DWARF 信息的 ELF 后，MemRW3 会自动解析全局变量、结构体字段和数组元素，不需要手工填写地址。

开始采集后，实际硬件链路是：

MemRW3 → USB 调试器 → SWD/JTAG → MEM-AP → MCU SRAM

为了提高速度，MemRW3 会把变量合并成去重的 32 位对齐读取槽，同一地址每轮只访问一次，并在连接期间持续复用 Core handle。

目前单变量全速采集可以达到 7 kHz+（注：测试环境为linux+有线且支持CMSIS-DAPv2协议的daplink+SWD为10MHz），实际速度取决于 Probe、SWD 时钟和目标芯片。

Chart 支持多曲线显示、FFT、坐标轴缩放、可见采样点标记和 CSV 记录。FFT 只使用最近一段连续采样，避免把暂停前后的数据错误拼接。

Table：变量与寄存器查看

Table 适合观察不需要连续波形的状态变量，支持递归显示结构体和数组，也可以直接写入基础类型变量。

Chart 和 Table 可以同时使用同一个变量。底层只读取一次：

一次 SWD 内存读取├── 连续样本送入 Chart└── 最新值送入 Table

Table 的显示刷新率只控制界面更新，不会降低底层采集率。

Table 右侧还可以加载 CMSIS-SVD 文件，浏览和读写外设寄存器。实际访问路径为：

Probe → SWD/JTAG → MEM-AP → AHB/APB → 外设寄存器

需要注意，部分状态寄存器存在读清零、写一清零或 FIFO 弹出等副作用，读取前仍应查看芯片手册。

Debug：源码断点与单步调试

DebugPlugin 使用 ELF/DWARF 建立源码行与机器指令地址的对应关系。

在源码中设置断点后，MemRW3 会找到对应的指令地址，并将它写入 MCU 的硬件断点单元。以 Cortex-M 为例，通常使用 FPB comparator：

源码行  → DWARF 解析指令地址  → 设置 FPB 硬件断点  → CPU 运行到对应地址  → 进入 Debug Halt

CPU 暂停后，MemRW3 会读取 PC、通用寄存器和栈内存，从而显示当前源码位置、汇编、调用栈和局部变量。

Step Into、Over 和 Out

指令单步由 MCU 的硬件调试单元执行：CPU 离开 Halt、执行一条指令，然后再次暂停。

源码级 Step 则可能需要执行多条指令，直到 PC 离开当前源码行。MemRW3 会结合 DWARF 文件路径、行号和调用栈深度判断 Step 是否完成。

不同 Step 的行为如下：

  • Step Into：逐条执行硬件单步，直到进入新的源码位置。
  • Step Over：遇到普通指令时使用硬件单步；识别到直接函数调用后，优先在返回地址设置临时硬件断点，让函数正常运行完成。
  • Step Out：优先根据调用栈恢复调用者地址，并在该地址设置临时硬件断点。
  • 如果没有空闲硬件断点，或无法可靠确定返回地址，则自动回退到连续硬件单步。

为什么单步时需要屏蔽中断

源码级单步最容易遇到的问题是中断干扰。

假设正在单步执行主循环，执行完一条指令后刚好触发 SysTick，PC 就会跳到中断处理函数。调试器可能误以为已经离开当前源码行，或者直接跟进 ISR。

为了避免这种情况，MemRW3 在 Cortex-M 的连续源码单步期间会临时设置并验证 PRIMASK，屏蔽普通可屏蔽中断，Step 结束后再恢复。

但是屏蔽中断也意味着依赖中断推进的代码可能无法继续。例如：

HAL_Delay(100);

HAL_Delay 通常依赖 SysTick 更新计数。如果 Step 没有使用硬件断点加速，而是回退到连续单步，SysTick 被屏蔽后延时条件不会变化，Step 就可能一直停留在等待循环中。

因此需要注意：

  • Step Into 通常采用连续单步，进入 HAL_Delay 或等待中断的代码后可能卡住。
  • Step Over 如果成功使用临时硬件断点加速，会先恢复中断状态，再让 CPU 正常运行到返回地址，因此可以正常处理 SysTick。
  • 硬件断点数量不足时，Step Over/Out 会回退到连续单步，此时同样可能遇到中断依赖问题。
  • NMI 和 Fault 不受 PRIMASK 屏蔽，发生后会立即结束当前 Step。
  • 遇到等待循环时，可以使用 DebugBar 的手动打断，或者直接 Reset。
  • 用户断点和 Step 使用的临时断点共享 MCU 有限的硬件断点资源。

DebugBar 会显示本次 Step 实际采用的是硬件断点加速还是 SingleStep，便于判断当前的执行方式。

基本使用流程

  1. 编译并加载带 DWARF 信息的 ELF；
  2. 选择芯片、Probe、SWD/JTAG 和通信速度；
  3. 连接目标设备；
  4. 将变量添加到 Chart 或 Table；
  5. 点击全局“开始”进行实时采集；
  6. 需要调试时，在 DebugPlugin 中选择 Attach 或 Reset；
  7. 设置源码断点并启动调试。
  8. 最后可以保存此次的配置，下次启动可以直接选择加载配置文件

建议使用较低的编译优化等级，并确保加载的 ELF 与 MCU 中运行的固件完全一致，否则变量地址、源码位置和局部变量可能不准确。

注意：若通信质量较差时（如使用无线时，或者有线但是线的质量较差时），连接时可能失败，连接失败时，建议等待通信链路稳定后重试；如果仍然失败，可降低 SWD/JTAG 速度，并检查目标供电、线缆、Probe 选择和芯片配置。

VariTree：静态变量解析与选择

VariTree 是 Chart 和 Table 共用的变量入口，负责从 ELF/DWARF 中解析变量名称、类型、层级和内存地址。

加载 ELF/AXF 后，可以按层级浏览：

  • 全局变量；
  • 结构体及嵌套字段；
  • 数组及元素原型，可通过 Index 切换具体下标；
  • 指针和基础数据类型；
  • 不同编译单元中的变量。

加载程序文件

点击变量树中的 ELF 加载按钮，选择与 MCU 当前固件一致、包含 DWARF 调试信息的 ELF 或 AXF。

加载完成后：

  • VariTree 显示静态变量树；
  • DebugPlugin 同时获得源码和调试信息；
  • 已添加到 Chart/Table 的变量可以重新匹配地址。

如果重新编译了固件，变量地址可能发生变化。重新加载 ELF 后应点击“追踪”，批量更新已经添加变量的地址。

查看变量属性

选中变量后，右侧属性区域会显示：

  • 变量名称和完整路径；
  • DWARF 原始类型；
  • 内存地址；
  • 数据大小；
  • 结构体字段或数组元素信息；
  • 用于显示和写入的 Extend 类型。

Basic 属性来自 ELF/DWARF，主要用于确认编译器提供的原始信息。Extend 属性用于告诉 MemRW3 如何解释内存中的字节，例如：

u8 / u16 / u32 / u64i8 / i16 / i32 / i64f32 / f64

通常 MemRW3 会根据 DWARF 类型自动选择，必要时也可以手动调整。

数组处理

为了避免大型数组在 VariTree 中生成成百上千个重复节点，变量树只保留一个元素原型。选中数组元素后，可以在右侧通过 Index 切换下标。

MemRW3 会自动计算实际地址：

元素地址 = 数组基地址 + 下标 × 元素大小

结构体数组同样支持下标切换，例如选择 samples[5].value 时，还会继续叠加 value 字段在结构体中的偏移。

具体使用方式有两种：

  • 添加到 Chart：选择数组元素或其中的基础字段，设置 Index 后添加，只连续采集指定元素。
  • 添加到 Table：直接选择整个数组添加，MemRW3 会根据元素原型展开全部元素；结构体数组还会递归展开各个字段。

重新编译固件并加载新 ELF 后，“追踪”功能可以根据 samples[5].value 这样的完整路径重新查找变量并更新地址。

对于很大的数组，建议只把需要观察的元素添加到 Chart；将整个数组加入 Table 会创建全部元素，并增加需要读取的内存槽位数量。

添加到 Chart

Chart 只接受具有固定地址、能够转换成数值的叶节点，例如整数、浮点数、结构体字段或数组元素。

操作步骤：

  1. 在 VariTree 中选中变量；
  2. 设置曲线名称和颜色；
  3. 点击“添加到 Chart”。

添加后，VariTree 只负责保存变量身份和地址；真正的连续采集与显示由 Chart 完成。

添加到 Table

Table 既可以添加基础变量，也可以直接添加结构体或数组。

操作步骤：

  1. 选中变量、结构体或数组；
  2. 设置显示名称；
  3. 点击“添加到 Table”。

添加结构体或数组后，Table 会递归创建对应的字段和元素，并允许分别控制每个叶节点是否参与采集。

地址追踪

固件重新编译后，即使变量名称没有变化，链接器也可能重新安排 SRAM 地址。

“追踪”功能会根据变量完整路径，在新 ELF 中重新查找已经添加到 Chart 和 Table 的变量，并统一更新采集地址，避免继续读取旧固件中的位置。

如果变量被删除、改名或类型发生较大变化，则需要重新选择并添加。

Chart 常用功能

添加实时曲线

  1. 加载 ELF；
  2. 在变量树中展开全局变量、结构体或数组；
  3. 选择一个基础类型变量；
  4. 设置曲线名称和颜色；
  5. 点击“添加到 Chart”；
  6. 连接 Probe，点击全局“开始”。

左击legend更改可见性，右击legend即可编辑对应曲线的属性

缩放可以直接用鼠标在对应的axis上拖拽，同时也可使用滚轮实现缩放有不同效果，ctrl+滚轮即为xy轴都缩放。

采集延迟设为 0 时使用全速模式。多条曲线地址相同或位于同一个读取槽时，底层会自动合并访问。

在使用无线是可把采集延迟适当调大以避免调试器无线波动导致负载积压并进一步恶化，导致在曲线上出现明显毛刺。

有线状态下的采集速率瓶颈通常是SWD IO速率，及轮询交互响应时间。

无线状态下的采集速率瓶颈通常是无线通信带来的交互延迟，故无线的采集速率明显比有线慢，故此时加点延迟不会带来明显的速率下降。

查看 FFT

点击 Chart 工具栏中的 FFT 按钮，即可同时显示时域波形和频谱。

FFT 支持：

  • Rectangular、Hann、Hamming、Blackman 窗函数；
  • 4～65536 个采样点；
  • X、Y 或双轴滚轮缩放；
  • 频率和幅值游标。

分析周期信号时建议先等待 Chart 积累足够数据，并选择合适的采样点数。

记录 CSV

  1. 在 Log 区域选择保存文件；
  2. 点击全局“开始”；
  3. MemRW3 自动写入时间戳和所有曲线数据；
  4. 暂停采集后自动关闭文件。

开始新一轮记录时会覆盖所选文件，需要长期保存时应先更换文件名。

Table 常用功能

查看变量当前值

  1. 在变量树中选择变量、结构体或数组；
  2. 点击“添加到 Table”；
  3. 开始采集。

Table 会递归展开结构体字段和数组元素。叶节点前的勾选框决定该变量是否参与实际采集。

每个叶节点可以设置 1～60 Hz 的显示刷新率。这个设置只影响界面更新频率，不影响 Chart 的底层采样率。

写入变量

在可写变量对应的输入框中填写数值，然后点击“写”。

MemRW3 会根据变量类型检查范围，例如：

  • u8：0～255；
  • i16：−32768～32767；
  • f32/f64：支持浮点输入。

写入最终通过 SWD/JTAG 和 MEM-AP 修改目标内存，因此应避免修改正在被中断或其他线程频繁更新的变量。

使用 SVD 寄存器

  1. 在 Table 右侧点击“加载 SVD”；
  2. 选择芯片对应的 .svd 或 .xml 文件；
  3. 展开外设和寄存器；
  4. 勾选需要监控的寄存器；
  5. 设置 1～30 Hz 的刷新率。

可写寄存器可以输入十六进制或十进制值。对于读清零、写一清零、FIFO 等特殊寄存器，操作前应确认芯片参考手册中的访问规则。

Debug 常用功能

启动调试

  1. 加载与目标固件一致的 ELF；
  2. 连接 Probe；
  3. 确认 DebugPlugin 已启用；
  4. 点击全局“开始”；
  5. 选择启动方式；
  6. 点击 Debug“启动”。

两种启动方式的区别：

  • Attach：保持 MCU 当前运行状态并接管调试；
  • Reset：复位 MCU，然后暂停在复位后的执行位置。

如果 ELF 中记录的是另一台电脑上的源码路径，可以在 DebugPlugin 中选择本机源码根目录（只会替换最顶层的公共目录）进行映射，若实际文件存在则会优先使用实际文件而非映射。

设置断点

打开源码文件后，可以通过以下方式切换断点：

  • 双击源码行；
  • 在汇编视图中双击指令。

MemRW3 会通过 DWARF 把源码行转换成机器指令地址，再安装 MCU 硬件断点。没有机器指令的空行或注释行会自动向后匹配最近的可执行行。

硬件断点数量由 MCU 决定，用户断点和 Step 使用的临时断点会共享这些资源。

暂停和继续

目标暂停后，DebugPlugin 会更新：

  • 当前 PC 和源码位置；
  • PC 附近汇编；
  • CPU 寄存器；
  • 调用栈；
  • 栈内存；
  • 当前栈帧局部变量。

点击调用栈中的其他栈帧，可以查看对应函数的源码和局部变量。

使用 Step

Step Over 和 Step Out 会优先使用临时硬件断点，让 CPU 正常运行到返回地址。此时中断可以正常工作。

如果没有空闲硬件断点，或者无法可靠确定返回地址，MemRW3 会回退到连续硬件单步，并在单步期间通过 PRIMASK 屏蔽普通中断，避免 SysTick 等中断把执行位置带入 ISR。

因此需要特别注意：

  • Step Into 进入 HAL_Delay 或等待中断的循环时可能无法结束；
  • Step Over 回退到 SingleStep 后也可能遇到相同问题；
  • DebugBar 会显示实际使用的是硬件断点加速还是 SingleStep；
  • Step 卡住时可以点击手动打断，必要时执行 Reset；
  • NMI 和 Fault 不受 PRIMASK 屏蔽，会直接终止当前 Step。

查看和修改局部变量

局部变量用的是probe-rs-debug在线解析，而由于目前probe-rs-debug只支持部分C语言的解析。对于starmclang编译器仅支持在-gdwarf-4的配置（starmclang默认-gdwarf-5不可用）下的C语言解析，且如果是cpp，则只可解析其C语言兼容的局部变量。

目标暂停后，在局部变量区域可以：

  • 展开结构体、数组和指针；
  • 查看整数、浮点、布尔、枚举和部分 C++ 基础类型；
  • 编辑具有实际内存地址的标量变量；
  • 按 Enter 或点击“写”提交。

优化构建中的局部变量可能位于寄存器、被拆分或已经被优化掉，此时不一定能够显示或写入。

若需要看静态变量可从Table界面查看。在目标暂停时Chart将不再更新，但Table中的变量仍会以1Hz的频率获取值，写入值和读写SVD不受影响。当目标恢复后Chart和Table行为自动恢复正常。

固件烧录

MemRW3 支持直接通过调试探针烧录：

  • ELF/AXF；
  • Intel HEX；
  • BIN；
  • UF2。

使用步骤：

  1. 连接目标设备；
  2. 点击控制栏中的“烧录固件”；
  3. 选择固件文件并确认目标芯片；
  4. 等待写入和校验完成。

烧录开始前，MemRW3 会暂停采集并独占 Probe Session。底层通常由 probe-rs 将芯片对应的 Flash Algorithm 加载到 MCU RAM，再由 CPU 执行擦除和写入操作：

固件文件  → Probe  → SWD/JTAG  → 下载 Flash Algorithm 到 RAM  → 擦除并写入 Flash  → 回读校验  → Reset

ELF、HEX 和 UF2 通常包含目标地址；BIN 不包含地址信息，因此 MemRW3 会自动使用目标芯片的启动 Flash 基址。

烧录完成后会进行校验并复位 MCU。重新开始调试前，应确保 DebugPlugin 加载的 ELF 与刚烧录的固件完全一致，否则源码断点、变量地址和局部变量解析可能不准确。

烧录过程中不要断开 Probe 或目标电源，芯片型号也必须选择正确。
