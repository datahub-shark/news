【资源分享】RMUL 2027 3V3 仿真地图：Gazebo Harmonic 场景与跨电脑移植包

新赛季联盟赛场地图纸发布后，我把 RMUL 2027 3V3 场地整理成了可在 Gazebo Harmonic 中使用的仿真资源，并打包了模型、纹理、世界文件、迁移脚本和说明文档，方便大家在其他电脑上查看场地，或接入自己的仿真工程。

本次分享版本为 2026-10-16 / STEP R1 / MAP_ONLY 发布版。场地几何由官方发布的 RMUL2027_3V3_V1.0.0.stp 转换而来，包含高地、中央控制区、隧道、工作台及围挡等结构。当前提供的是场景资源和集成工具，使用前可以先通过独立查看模式确认效果。

地图转换、尺寸理解、材质设置和移植说明中可能仍有不准确或遗漏之处，欢迎大家批评指正。如果发现与官方规则、图纸或实际运行效果不一致的地方，欢迎在评论区附上依据或复现信息，一起完善。

图1：默认纹理场景，仅加载场地与拍摄相机，不包含机器人。

一、这个包可以做什么

  • 查看新场地：安装好 Gazebo Harmonic 后，可以不依赖原机器人工程，单独打开场景。
  • 接入仿真工程：提供 SDF 世界、DAE 网格、本地纹理和场地参数，方便按自己的项目结构适配。
  • 跨电脑移植：附带文件校验、已知工程布局的安装脚本、依赖说明和迁移步骤。
  • 核对几何：保留原始 STEP、尺寸复核记录，以及默认纹理和 CAD 原始面颜色两种外观。

适用环境为 Ubuntu 24.04 / WSL2 Ubuntu 24.04、Gazebo Harmonic（Gazebo Sim 8）；与原哨兵工程集成时使用 ROS 2 Jazzy。

这里分享的是 RMUL 2027 3V3 地图，不包含 1V1 地图、完整机器人项目或比赛裁判系统。仅查看场地无需完整 ROS 工程；运行机器人、传感器和桥接则需要相应工程与依赖。

二、地图来源与 STEP R1 更新

官方来源为 RoboMaster 高校赛务发布的 《RMU 2027场地图纸&可移动道具开源》。规则参考《RoboMaster 2027 机甲大师高校联盟赛比赛规则手册》V1.0.0（2026-10-15）。

这一版直接转换 STEP 几何，并用同一份转换后的几何作为场地显示和碰撞资源。相较早期按手册尺寸搭建的简化版，补充、修正了围挡盖板、工作台绝对高度、中央控制区表面以及隧道端部等细节。

场地内侧西南角设为 (0, 0)，东为 +X，北为 +Y，主地面完成面为 Z=0；红方位于西北，蓝方位于东南。以下数值用于说明本包采用的 CAD 几何：

项目STEP R1 采用值
内场范围12 m × 8 m
含围挡外轮廓12.6 m × 8.6 m
围挡顶部高度420 mm
高地顶面高度200 mm

中央控制区顶面高度10 mm，标识最高 11 mm

隧道通道薄面至板底的几何净空249.5 mm

以上高度统一相对主地面完成面，不能直接混同于规则中的部件标称高度或材料厚度。详细测量依据见包内 docs/RMUL_2027_STEP_AUDIT.md 和 step_measurements.json。

官方原帖说明图纸用于参考；如与规则手册或现场场地存在出入，应以规则手册和现场场地为准。本包也沿用这一使用边界。

四、快速使用：只查看地图

前提是已安装 Gazebo Harmonic，且图形环境支持 Ogre2。在 Ubuntu 或 WSL2 的 Linux 目录中，将 ZIP 解压到新目录，例如 ~/projects/，进入解压后的包根目录：

python3 verify_package.py
bash scripts/view_field.sh

第一条命令只依赖 Python 3.10 或更新版本的标准库，用于校验文件；第二条启动场地，不加载机器人、SLAM 或 Nav2。

场地模型和纹理均在包内，运行已生成的地图不需要在线下载 Fuel 场地资源，也不需要原始规则 PDF。Gazebo、ROS 及其他系统依赖仍需自行安装。

五、接入已有工程

如果已经有完整的 guodong-sentry-sim 工程，可以使用附带安装脚本。假设原工程位于 ~/projects/guodong-sentry-sim，从地图包根目录执行：

# 先检查目标工程布局
python3 install_into_sim.py --repo "$HOME/projects/guodong-sentry-sim" --check

# 兼容性检查通过后安装
python3 install_into_sim.py --repo "$HOME/projects/guodong-sentry-sim"

# 构建并启动
bash scripts/build_integrated.sh "$HOME/projects/guodong-sentry-sim"
bash "$HOME/projects/guodong-sentry-sim/scripts/rmul_2027.sh"

脚本针对原项目的已知布局设计，保留旧地图，并生成备份与安装记录。使用其他队伍的工程时，需要自行适配模型资源路径、世界加载、机器人出生点和传感器配置；请不要直接覆盖自己的 launch 文件。

集成后，默认世界 rmul_2027 使用手册纹理风格；可以切换到原始 CAD 面颜色：

bash "$HOME/projects/guodong-sentry-sim/scripts/rmul_2027.sh" world:=rmul_2027_native

两种外观使用相同场地几何。已生成场景的运行不需要 OpenCascade；重新从源 STEP 转换时才需要对应的 OCP 环境，详见包内文档。

六、验证范围和当前限制

包内源电脑记录的环境为 Ubuntu 24.04 / ROS 2 Jazzy / Gazebo Harmonic，STEP R1 记录包含 40 项静态回归通过，以及场景渲染、相机、点云、720 束激光和一次低速西墙接触检查。

上述数据是包内保存的源电脑历史记录。此次发布另行运行了不加载机器人的场景，重新拍摄纯地图预览图，并核验发布包的文件完整性；没有重新开展机器人传感器、导航或全地形验收。接入自己的机器人后，仍需重新检查资源加载、坐标、碰撞、传感器与导航表现。

使用时还需要注意：

  • 原配套底盘采用关闭重力的平面速度控制，登高、轮地接触和地形跟随尚未适配，不能据此认定机器人已经能够通过所有地形。
  • 原机器人水平激光高度约 279.62 mm，可以扫过较低的高地和隧道顶部；激光可见范围不能直接等同于底盘可通行范围。
  • 附带 PGM/YAML 是面向原平面底盘的保守通行投影，分辨率 2.5 cm/格，原点 [-0.4, -0.4, 0]；它不是 SLAM 实测结果，也没有完成新场地 AMCL/Nav2 导航验收。
  • 当前未实现 RFID 交互、占点结算、回血、弹丸与比赛裁判逻辑。
  • 材质、摩擦等仍存在建模假设，CAD 几何和显示颜色不代表实物动力学参数。
