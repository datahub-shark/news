1. 项目介绍

1.1 整体介绍

本项目是T-DT战队2026年雷达站的完整开源，包含了无线电解码，反制无人机以及雷达识别，各个模块相对独立，因此，在没有无线电信息时，系统仍可独立运行雷达—相机后融合方案；在没有激光雷达时，也可使用单目相机方案完成目标定位。

本次开源由两个相互配合的项目组成：

  • T-DT_Radar：完成相机目标识别、激光雷达点云处理、多传感器后融合、无人机跟踪及反制控制。开源链接 ：https://github.com/T-DT-Algorithm-2026/T-DT_Radar
  • RM_sdr：使用 SDR 采集宽带无线电信号，在 GNU Radio 中完成多信道下变频、滤波和 GFSK 解调，再进行 CRC 校验与协议解析，向雷达系统发布机器人坐标、比赛状态和干扰密钥等 ROS 2 消息。开源链接 : https://github.com/T-DT-Algorithm-2026/RM_sdr

系统具有以下特点：

  1. 相机与激光雷达采用后融合架构，不依赖相机—雷达联合标定和严格的帧间匹配，降低机械结构、传感器时序和扩展数量对系统的限制。
  2. 使用 GICP 自动完成激光雷达与场地地图的配准，减少赛前手工部署时间。
  3. 采用三级视觉识别网络，分别完成机器人检测、装甲板检测和数字分类，在保证识别能力的同时降低模型训练与数据整理成本。
  4. 使用卡尔曼滤波跟踪点云目标，并将视觉识别结果与轨迹匹配，实现类别信息与空间位置的融合。
  5. 无线电链路能够以单台 SDR 并行接收信息波和多个干扰信道，并与视觉、点云定位结果自动切换。
  6. 反制模块同时利用雷达三维目标、视觉像素目标、云台反馈和比赛信息，实现非同轴安装条件下的无人机锁定、预测与反制。
  7. 各功能以 ROS 2 消息连接，传感器、识别、融合、无线电和反制模块可独立调试、替换与扩展。

项目的主要硬件包括 Livox Avia 激光雷达、Hikvision CH-120-10UC 单目相机、微相 ANTSDR 软件无线电、Intel i7-12700KF 处理器及两张 NVIDIA RTX A4000 GPU；反制模块另使用 Hikvision CS-016 相机和两台 6020 电机。仓库提供除串口、相机驱动和模型训练以外的雷达站功能。

2. 项目设计

2.1 项目背景

26规则给雷达站增加了反制无人机的任务，大幅度提高了雷达的战术地位，同时增加了无线电解码，拓展了雷达可以获得的信息，使雷达真正的成为了”全视之眼“，为队伍的战术规划和哨兵的决策作出贡献，同时无线电包含的坐标信息也大幅度提高了雷达的标记准确率，提高了雷达的上限，同时也带来了技术上的挑战。

2.2 设计思路

无线电提供的坐标信息的准确度远超与雷达主程序得到的坐标，所以本项目选择了无线电坐标优先，雷达坐标其次的关系，优先采用无线电坐标。

反制无人机由于无人机距离很远，并且无人机的激光检测模块较小，导致pnp结算效果较差，所获得的信息较少，所以本项目将目标跟踪转移到二维平面上，同时采用了球坐标卡尔曼去进行预测，达到了很好的效果。同时为了配合战术，反制应该有操作手来决定是否开启，我们利用了与哨兵的通信链路以达到操作手的控制。

2.3 核心算法

2.3.1 基于卡尔曼轨迹的传感器后融合

融合模块首先使用卡尔曼滤波器对激光雷达识别到的目标进行连续跟踪，以目标的运动状态维持稳定轨迹；随后将相机输出的机器人类别与装甲板识别结果同卡尔曼轨迹进行匹配；最后综合滤波结果和视觉识别结果，输出带类别的场地坐标。

这一流程直接在各传感器已经生成的目标结果上完成关联。相机负责提供类别语义，激光雷达负责提供三维位置和运动轨迹，两条链路可以独立运行。无线电发布的 robot_position 坐标作为另一信息源接入系统，系统可根据实时可用性在雷达定位信息和无线电信息之间自动切换。

2.3.2 宽带 SDR 多信道并行接收

无线电子系统使用一台 SDR 对覆盖信息波和多个干扰波的频段进行一次宽带 IQ 采样。GNU Radio 为各频点建立独立的数字下变频、FIR 信道滤波和抽取支路，将信号搬移到各自基带并行处理。该架构无需轮询切换频率，也不需要为每个信道配置独立接收设备，因此能够同时获得主信息和干扰波携带的密钥，并保证所有信道共享同一硬件采样时钟。

GNU Radio 与 ROS 2 之间通过本机 ZeroMQ PUB/SUB 解耦。射频侧只负责信道化和解调；ROS 2 节点为每个端口维护独立缓存，完成连续字节流重组、协议校验和强类型消息发布。主数据、干扰信道 1、干扰信道 2 和可选干扰信道 3 分别使用 5555、6666、6667 和 6668 端口。

2.3.3 基于符号极性前缀和的访问码搜索

信息波与干扰波分别使用 64 bit 访问码 0x2F6F4C74B914492E 和 0x16E8D377151C712D。接收块先将鉴频后的浮点采样按极性映射为 +1/-1，再建立前缀和：

prefix[i + 1] = prefix[i] + sign(sample[i])
symbol_sum(begin, end) = prefix[end] - prefix[begin]

候选位置 p 的访问码相关分数为：

score(p) = Σ kernel[bit] × symbol_sum(bit_begin, bit_end)

朴素相关在每个候选位置需要重复处理约 64×SPS 个采样；前缀和算法只需计算约 64 个符号区间。在当前 SPS=47 时，相关核心的计算规模从约 3008 次采样累加降为约 64 次区间计算，理论上缩减约 47 倍。这里的 47 倍仅描述相关核心的计算规模，并不代表整个程序获得相同倍数的性能提升。低复杂度搜索为多个信道的实时并行解码提供了算力基础，极性相关也降低了绝对幅度变化对帧搜索的影响。

2.3.4 基于距离的动态激光落点与非同轴转换

反制模块使用 12 m、16 m、20 m 和 24 m 四组激光落点标定数据，对图像中的 x、y 方向分别拟合：

target = A / distance + B

收到激光雷达输出的空中目标三维点后，程序计算目标距离，并实时更新该距离对应的图像激光落点。视觉控制使用动态落点与无人机像素位置之间的偏差，而非固定图像中心，因此相机、激光和云台可以采用非同轴安装。

系统同时发布 pitch_link 到 camera_link 的静态坐标变换，将雷达目标点转换到相机坐标系后计算首次锁定角度。机械结构发生变化时，只需重新测量相应外参和偏置。

2.3.5 球坐标卡尔曼预测与反制状态控制

视觉检测得到无人机像素坐标后，程序根据相机焦距把像素误差转换为 yaw、pitch 角度误差，并与对应时间附近的云台姿态相加，得到目标的绝对角度测量。卡尔曼滤波状态包含目标角度和角速度；每次视觉测量到达时更新状态，再结合图像采集至当前时刻的延迟和 control_delay_s，预测控制指令真正生效时的目标角度，从而补偿检测噪声和系统延迟。

当视觉消息超过 1 秒未更新时，滤波器重置，系统使用雷达目标点完成首次锁定和巡航。match_info 消息向反制模块提供比赛剩余时间、对方无人机反制状态和哨兵指令。程序记录反制次数，在单次反制结束后按照配置等待，并结合剩余比赛时间决定是否跳过等待；比赛信息超时后，则按预设的失联逻辑处理开火状态。
