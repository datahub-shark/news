一、 项目背景

在 RoboMaster 自瞄系统的长期迭代中，算法、设备驱动、通信与调度逻辑往往随功能开发逐渐耦合：一次算法调整可能牵动整套工程；多人并行开发时，算法版本与接口难以保持一致；为不同兵种复用模块时，也容易产生大量重复集成工作。

RP-26AutoAim-Frame 是我们在 2026 赛季区域赛后，针对上述工程协作问题设计的插件式自瞄框架示例。项目将稳定的运行时、插件接口与 Context 通信网络抽离为核心框架，把具体功能组织为可独立编译、按需加载和替换的动态插件。

本项目的目标是为自瞄系统提供一个轻量、低耦合、可扩展的工程基础：开发者可以围绕固定接口并行实现算法或设备模块，通过配置组合运行链路，并在不修改主程序的前提下完成验证、替换与回滚。

项目没有直接采用 ROS。ROS 提供了成熟的节点与通信生态，但本项目更侧重比赛场景中运行链路的轻量化、低耦合与可控性，因此采用了面向自瞄任务的最小运行时与通信机制。


二、框架设计

1. 框架模块与业务算法分层

框架核心代码位于 src/core，负责提供：

  • 插件基类、业务接口与通用数据类型；
  • 基于 Context 的模块通信网络；
  • 动态库加载、插件注册与工厂机制；
  • 运行时入口 app；
  • 通用算法与基础工具库。

业务算法位于 src/app_plugin。插件只实现具体业务处理，不直接耦合主程序；app 不包含具体插件头文件，也不直接链接具体插件库。

# 目录结构
RP-26AutoAim-Frame/
├── src/
│ ├── core/                     # 核心框架、接口、运行时与工具库
│ └── app_plugin/               # 最小可运行插件示例
├── config/
│ └── runtime_config.json       # 插件加载顺序与线程组配置
├── output/                     # 可执行文件与库的统一输出目录
├── build/                      # CMake 构建目录
├── README.md                   # 框架说明与开发约定
└── CMakeLists.txt              # 顶层构建入口

2. 动态加载与配置驱动

每个插件被编译为动态库，并通过 REGISTER_PLUGIN(...) 完成注册。运行时读取 config/runtime_config.json，按配置指定的名称、动态库和顺序加载插件。这种方式让系统功能组合从 “修改并重新组织主工程” 转变为 “替换插件与修改配置” ，方便模块独立开发和不同方案快速切换。

3. Context 通信网络

插件通过 Context 获取发布端与订阅端，按约定传递标准数据类型。接口层通过 declare() 描述输入输出数据，业务实现则聚焦于 process(const app::Context &context) 中的一轮处理逻辑。通信接口在插件在内缓存，避免在每次调度中重复查询；process() 完成一轮处理后应返回，不应自行维护永久循环，以便运行时统一调度。

# 插件模块的输入输出声明
class Detector : public app::PluginBase
{
public:
    void declare(app::Context &context) override;
};

inline void Detector::declare(app::Context &context)
{
    context.declare_input_buffer<InputFrame>(this);                  //声明输入
    context.declare_output_buffer<InputFrameWithNNResults>(this);    //声明输出
}

4. 可配置线程组

未设置 AttachTo 的插件拥有独立线程组；设置 AttachTo 后，插件会加入目标插件所在的线程组。组内插件按配置顺序循环调用 process(context)。

默认配置中的插件加载顺序如下：

ReceiveDecoder → CameraManager → NNDetector → TrackerManager → PlannerControl → SendEncoder

其中 SendEncoder 附加到 PlannerControl 所在线程组，使火控计算与发送链路可在同一调度组中顺序执行。即默认链路共有6个插件，组成了5个线程组。

四、快速上手

1. 环境要求

  • Ubuntu 22.04 或更高版本；
  • 支持 C++20 的编译器：GCC 11+ 或 Clang 14+；
  • CMake 3.22+；
  • OpenCV 4.8+、Eigen3、Sophus、Google glog。

项目已内置 Foxglove SDK，无需额外安装。

2. 编译与运行

git clone https://github.com/SZURPVision/RP-26AutoAim-Frame.git
cd RP-26AutoAim-Frame
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel 2
./output/app


五、插件开发指南

新增插件通常只需完成以下步骤：

  1. 在 src/app_plugin/<module_name> 下创建模块目录
  2. 继承 src/core/app/interface 中对应的接口；
  3. 实现 process(const app::Context &context)；
  4. 在源文件中使用 REGISTER_PLUGIN("Name", Type) 注册插件；
  5. 在插件 CMake 中构建 SHARED 动态库，并链接 app_interface_lib 与 class_loader_lib；
  6. 在 config/runtime_config.json 中配置插件名称、库文件名和可选的 AttachTo 关系。

插件注册名必须与运行时配置中的 name 完全一致；动态库文件名必须与 library 字段一致。插件库无需链接 app，运行时会按配置完成加载。
