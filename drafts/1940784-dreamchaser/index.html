方案选择历程

方案一：端到端方案（分区赛前）

分区赛前，我们最初选择的是类似 EfficientPose 的端到端方案。但由于当时没有实体科技核心，我们既无法实际拍摄数据集，也无从验证想法的可行性。分区赛期间，在与其他学校的交流中，我们发现几乎没有队伍选择端到端路线。同时，我们在分区赛现场拍摄的数据集质量较差，而科技核心的制作工期又较长——端到端方案高度依赖数据集质量，这意味着一旦数据集拍摄效果不佳，我们将无法通过调整代码来挽回精度。综合考虑，我们放弃了端到端方案。

方案二：点云配准方案（分区赛后）

分区赛后，通过与其他学校的交流，我们转向了「点云粗配准 + 精配准」的解算方案，目标是求解兑换柱中心的 6DoF 位姿。硬件选型上，我们选择了留形科技的 Odin1 作为图像与点云的采集相机。然而，在编写了半个月代码、Odin1 到货试用后，我们发现它在近距离下的点云质量非常差：经 ROI 裁剪出兑换柱范围并可视化后，兑换柱的点云几乎完全是噪声，无法通过聚类、几何约束等手段修复。此时已是 7 月 20 日左右，无论时间还是经费都不允许再更换其他深度相机。因此，我们不得不放弃点云方案。

方案三：关键点 + PnP 方案（最终上场方案）

放弃点云方案后，我们注意到了港科大 Enterprize 战队的开源代码。他们使用合成数据训练出了一个能够提取科技核心整体 12 个关键点的神经网络。经过试用，我们认为效果非常理想，于是基于港科的开源权重，补全了从关键点到 PnP 解算、再到位姿转换的完整流程。测试结果达到预期，这一版方案最终成为国赛上场方案，并在 16 进 8 的最后一场比赛中发挥了实际作用。

 1.方案一 pipeline

   相机图像 → YOLO 2D 检测得到 ROI → 按 ROI 裁剪 Odin 点云 → FPFH 特征匹配加 RANSAC 粗配准 → Point-to-Plane ICP 精配准 → 配准结果取逆后经 TF 广播转换位姿 → 串口发送位姿到下位机。

 2.方案二 pipeline

   相机图像 → 关键点神经网络回归 12 个关键点 → 关键点筛选，12 点筛到 11 点 → RANSAC PnP 解算 → 滑动窗口滤波 → 相机系位姿经标定矩阵变换到车体系 → 串口发送位姿到下位机

2. 选型结论

方案二并没有理论上更优，而是在本赛季硬件，经费，时间等条件下唯一能跑通的方案。方案一的失败不在算法，而在传感器与目标尺寸不匹配。选型结论是，约束条件决定方案上限，预研阶段要先用最坏工况验证传感器，再谈算法。
