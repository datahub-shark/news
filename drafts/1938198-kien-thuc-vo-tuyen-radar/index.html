1.项目介绍

1.1 项目简介：

本项目以工业单目相机目标检测为核心，经位姿解算、运动预测与激光轴逆解，构成「检测—解算—瞄准」完整闭环。上位机完成检测、解算与提前瞄准，下位机仅接收瞄准角指令并回传云台姿态，感知与执行分层解耦，精度高、延迟低。


1.1雷达反制总览

系统具备较强容错能力：如遇到突发情况（如跌落/剧烈震动）使反制精度受损，可于比赛的3分钟准备阶段按w进行约 4s 的赛场内置次级标定，即可支撑除预测外的全部功能，卡尔曼预测与高精度提前瞄准则依赖完整的标定链路。推理兼容 OpenVINO / TensorRT，取流适配海康工业相机；检测、解算、标定与通信参数均可在配置文件中调整，可拓展性强、造价低（有架子/云台/相机就能跑）。配套手眼与激光光轴标定工具，以及赛后回放模式，便于快速复现与持续迭代。


1.2 项目亮点：

• 模块化架构：检测、解算、串口、标定与测试模块相对独立，标定工具提供独立可执行程序，主程序支持 test 模式进行赛后回放复盘。

• 双模型目标检测：采用主色 + White 双模型检测方案，兼容 OpenVINO / TensorRT 推理后端，主要参数可通过配置文件调整。

• 较强的结构适应能力：实际比赛中曾使用一侧已弯曲的手机三脚架与 3D 打印云台进行反制，在打印件形变、参数漂移及云台持续晃动等非理想条件下，仍完成了单局 5 次反制。

• 分层空间标定：针对相机与激光器相对于云台旋转中心存在空间偏置的安装方式，建立“手眼标定 → 激光发射点几何标定 → 光轴残余误差标定”的分层标定链路，实现对实际安装偏差的空间建模与补偿。

• C++ 三维实时闭环：基于 C++ 构建实时闭环，在三维空间完成目标 PnP 解算、运动预测与激光轴指向求解；无需严格保证相机与激光器同轴，也无需将激光器安装于云台旋转中心。

3 算法迭代与误差补偿方法

系统初期即具备基于目标检测与 PnP 的三维位置解算能力，并在此基础上完成了基本的目标跟随与激光反制 Demo。随着系统由功能验证逐步进入实际反制测试，原有方案在机械安装、结构稳定性以及激光指向等方面逐渐暴露出新的误差。与理想条件下将各安装参数视为固定值的处理方式不同，本章节以回忆实际测试中出现的问题为依据，在已有三维解算框架上逐步增加空间位置补偿、姿态补偿、方向修正、快速标定及运动预测等环节，使算法能够适应实际比赛中的非理想工况。

3.1 激光器偏心导致的空间位置误差

问题

初始系统已经能够通过 PnP 获得目标在相机坐标系下的三维位置，并完成基本的目标跟随。然而，在实际激光反制测试中发现，即使目标的三维位置解算基本准确，激光实际落点仍与理论瞄准位置存在偏差。

进一步分析发现，激光器并未安装于云台旋转中心，而是相对于旋转中心存在一定的空间偏移。若直接将云台旋转中心近似为激光发射点，则云台转动过程中激光实际发射位置的变化无法被描述，从而产生额外的空间指向误差。

3.2 支架抖动导致的 Roll 不稳定

问题

完成激光器偏心建模后，系统在静态条件下的指向精度得到改善，但进入实际使用环境后又出现了新的误差来源。

由于云台支架和安装结构刚度有限，机体受到轻微外力时即可使整个云台产生连续晃动。与此同时，支架自身姿态发生变化会使云台 Roll 随之变化，因此实际 Roll 并不能始终保持在某一个固定值。

如果继续将 Roll 视为常量，则支架发生倾斜或晃动时，算法使用的云台姿态将与实际姿态产生偏差，进而影响激光发射点的位置计算以及后续指向求解。

解决

针对这一问题，我们决定不再将 Roll 进行固定值近似，而是利用下位机实时反馈的 Yaw、Pitch 和 Roll 建立当前云台姿态：

其中 ψ、θ、ϕ 分别表示当前 Yaw、Pitch 和 Roll。

虽然两轴云台无法主动控制 Roll，但 Roll 是可测量而非不可观测的状态。因此，我们将实时 Roll 纳入空间姿态计算，而不是要求 Roll 始终趋于某一固定值。

同时，程序根据图像时间戳与串口姿态时间戳进行匹配，选择与当前图像对应的云台姿态参与解算，使目标位置与云台姿态尽可能处于同一时刻。

通过这一处理，支架的轻微晃动不再直接等价于算法模型失效，而是转化为当前姿态变化，并由实时姿态参与后续激光位置与方向计算。

3.4 相机光轴与激光轴不共轴

问题

完成激光器偏心补偿和云台指向计算后，我们发现系统在实际测试中对于近距离目标的精度已大体达标，但对于远距离的目标仍存在较为稳定的方向性偏差。

进一步分析发现，相机光轴与激光器实际发射轴并不共线。也就是说，相机通过 PnP 得到的目标方向，本质上描述的是相机看到的目标方向，而不是激光器真正需要指向的方向。

因此，即使前面的目标位置解算和云台角度计算完全正确，两条不同的光轴之间仍会产生固定的系统误差。

解决

针对这一问题，我们选择将相机与激光器之间的方向偏差单独作为标定参数进行处理，以 `rpy_cam_to_ray` 表示两者之间的旋转关系：

其中 (α,β,γ) 为相机光轴到激光方向的残余姿态偏差。

通过将该方向偏差从激光器位置偏心模型中独立出来，系统实际上将激光安装误差分成两个部分：

激光器安装在哪里→`ray_to_gimbal`

激光器实际朝向哪里→`rpy_cam_to_ray`

这样能够正确解释激光器真正需要指向的方向，同时避免使用单一参数同时吸收位置误差和方向误差，提高标定链路的可解释性。


3.5 结构形变下的快速标定与多距离补偿

问题

完成上述几何误差补偿后，系统在结构状态稳定时能够获得较好的指向效果。然而，实际使用中的 3D 打印结构并非完全刚性，运输、碰撞以及机体受力均可能使激光器的安装状态发生轻微变化。

实际测试表明，这种结构形变并不一定导致系统完全失效，但会使原有标定参数产生漂移，使上一局得到的参数在下一局中不再完全适用。

另一方面，即使通过单一距离重新标定，在改变目标距离后仍可能出现一定的落点变化。这说明结构偏移造成的角度误差还具有明显的距离相关性。

因此，需要同时解决结构形变导致的参数漂移和目标距离变化导致的残余误差。

解决

针对比赛现场无法进行完整标定的问题，我们设计了快速单距离标定流程。

当目标稳定跟踪并获得有效的 LASER_REF 后，通过 W 键进入快速标定流程，操作者依次指定模拟激光位置和实际击打位置，程序根据当前目标深度和两点之间的空间方向关系重新计算 `rpy_cam_to_ray`。

该过程不重新进行完整手眼标定，而是主要修正当前机械状态下的残余光轴方向误差，因此可以在较短时间内完成参数恢复，适用于比赛准备阶段的现场粗调。

通过多距离数据拟合，可以进一步得到一组趋于真解的 `ray_to_gimbal` 和`rpy_cam_to_ray`的修正参数，从而减小不同工作距离下的系统性误差。

因此，系统最终形成两级标定策略：单距离快速标定→比赛现场粗调 ​|  多距离拟合→场下细调​

将需要大量测试数据的精细标定工作放在场下完成，而比赛现场只保留耗时较短的快速调整环节，在实际比赛条件下兼顾了标定速度和反制精度。


3.6 系统延迟与运动目标的提前瞄准

问题

完成静态目标的空间解算、姿态补偿以及激光指向修正后，系统进一步面对运动目标时又出现了新的问题。

从相机采集、目标检测、PnP 解算，到云台角度计算以及下位机执行，整个闭环存在不可忽略的时间延迟。因此，即使系统在计算时准确获得了目标位置，云台真正执行瞄准时目标也可能已经发生位移。

对于运动目标，单纯瞄准当前检测位置无法补偿这一时间差。

解决

理论上可以建立更加复杂的目标运动模型，但本项目的实际测试条件对模型复杂度形成了限制。由于无人机真实飞行测试难以频繁进行，能够获得的有效运动数据数量有限，少量测试数据不足以支撑复杂运动模型的可靠参数估计与调试。因此，系统没有直接采用完整的非线性 EKF，而是在现有代码框架下采用基于位置—速度状态的简化常速度模型进行短时间预测。

3.7 小结

通过实际反制测试，我们反制的算法并非一次性完成，而是在已有三维目标解算框架的基础上，针对实际工况中逐步暴露的问题进行连续迭代。

首先，针对激光器偏心建立实际激光发射点模型；随后发现支架抖动导致 Roll 不稳定，因此引入实时云台姿态参与空间计算；在此基础上，通过解析求解与局部搜索完成两轴云台的实际指向。进一步针对相机光轴与激光轴不共线的问题，引入独立的光轴方向标定。

当系统进入实际比赛环境后，又进一步针对 3D 打印结构形变造成的参数漂移建立单距离快速标定，并在场下通过多距离数据完成距离相关误差补偿。最后，针对运动目标情况下系统延迟造成的瞄准滞后，采用参数量较少的简化常速度预测模型进行提前瞄准。由此形成了这一完整的系统算法流程及误差补偿链路：
